# 简洁交互文档写作风格

用于把设计稿中无法完整表达的行为，转化为简洁、可实现的研发说明。示例仅用于展示表达方式，不代表任何项目的默认业务规则。

## 表达方式

- 按功能模块及关键行为组织，以短句为主，配相关设计截图。
- 用明确动词描述结果：禁用、关闭、保留、清空、停止、重新播放。
- 单条交互说明使用无序列表；同组列表项紧密排列，中间不留空行。
- 标准行为不赘述，重要差异明确写；共用交互引用一次即可。
- 复杂冲突用具体场景澄清；有规律的状态可用小表格。
- 未决项就地标注，不把文档扩展成问题审计报告。

## Markdown 排版示例

正确格式：

```markdown
## 1. 任务列表

### 1.1 查看任务

- 默认展示今天的任务。
- 点击日期区域打开日期选择器；选择日期后，列表同步更新。
- 选择过去日期时，“新增任务”按钮禁用。

### 1.2 状态说明

| 状态 | 页面反馈 |
| --- | --- |
| 加载中 | 展示加载状态，保留页面框架 |
| 空数据 | 展示空状态及新增入口 |

- 状态切换后保留当前日期筛选。
```

不要在同组列表项之间加入空行：

```markdown
- 默认展示今天的任务。

- 点击日期区域打开日期选择器。
```

不要让标题、表格或列表紧贴其他内容块。标题后、列表前后、表格前后均保留一个空行。

## 参考案例中的有效表达

以下仅演示表达粒度，实际项目必须有相应依据。

**返回与数据保留**

- “任务确认”页点击返回，回到“任务输入”页，并保留已输入的内容。

**操作的影响范围**

- 存在日期筛选时，“清空”仅删除筛选后的记录。

**手势与布局的区别**

- 指针固定，仅时间轴可左右拖拽。

**并行状态的关系**

- 进入全局操作状态时，暂停当前流程；退出后从中断位置继续。

**需要例子才能消除的歧义**

- 浮层展示期间，首次点击背景只关闭浮层，不触发背景控件。

**流程概括**

- 输入内容 → 预览结果 → 确认提交。

## 不应继承的偶然特征

参考材料中的空标题、待定参数、拷贝重复和讨论项不应原样固化进模板。若一处把规则标为待讨论，另一处又给出确定结论，应核实有效版本，不自行裁决。

不同产品需要关注的交互重点不同。仅检查当前功能真实涉及的规则，不为追求形式完整而补充无关模块。
